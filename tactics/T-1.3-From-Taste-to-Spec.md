# 🧩 T-1.3 戰術轉化：從「職人品位」到「技術規格」

## 1. 戰略背景 (Context)
*   **痛點**：高階管理者（如：陳大文）對 AI 產出的「不滿意」通常是感覺上的（Vibe），難以轉化為技術端的 Prompt 改進。
*   **目標**：透過 Wing Group 的偵測，將 L4 的「職人手感」格律化為 L2 的「測試集規格」。

## 2. 轉化模式 (The Pattern)
1.  **偵測 (Detection)**：捕捉 L4 中「我討厭...」或「這看起來不對...」的負面案例紀錄（I-CLI-16）。
2.  **解構 (Deconstruction)**：
    *   問：為什麼不滿意？ (答：語氣太僵硬，沒抓到預算重點)
    *   問：正確範例是什麼？ (答：2025 年的那份報告)
3.  **規格化 (Specification)**：
    *   將正確範例抽取出「黃金樣本集 (Golden Dataset)」。
    *   將負面案例標註為「幻覺基準點 (Hallucination Baseline)」。
4.  **注入 L2 (Vessel Pushing)**：更新企業職能庫的評測集。

## 3. 實戰範例 (Artifacts)
*   **L4 手感輸入**：「我受夠了 Agent 每次都把健保申報碼漏掉，這讓我看起來很不專業！」
*   **轉化後 L2 規格**：在 `L2_Audit_T_Pattern` 新增強制性檢核項：「申報碼欄位不可為空，且必須符合 regex `^[A-Z][0-9]{9}$`」。

## 4. 關鍵連結 (Success Link)
*   **PE.04 (對位精準度)**：透過此轉化戰術，陳大文發現 Agent 的「默契」大幅提升，原本需要改三次的報告現在一遍就過。
